# 关键词交互 · 无痕投射测试 · 技术规格与产品形态

> 本文档是「MBTI 16型人格 · 罪案侧写互动叙事」项目的**交互层核心方案**。
> 定义了一种“不依赖选择题、不依赖问卷、不触发防御心理”的沉浸式人格投射机制。
> 基于已验证的HTML可交互原型（第一案·猎杀营）归纳提炼。


## 一、项目定位

### 1.1 核心目标
构建一种**新的交互形态**，让参与者在完全不知道“自己在被测试”的前提下，通过自然探索行为，完成MBTI人格偏好的投射与记录。

### 1.2 与传统测试的对比

| 维度 | 传统MBTI问卷 | 本方案（关键词交互·无痕投射） |
| :--- | :--- | :--- |
| 交互形态 | 选择题（93道/标准版） | 自由输入关键词探索场景 |
| 读者心态 | “我在做题” → 防御心理启动 | “我在破案/探索” → 沉浸状态 |
| 数据来源 | 答题者的自我陈述 | **阅读行为**（输入顺序、关注点、忽略点） |
| 结果形态 | 四字母标签（INTJ / ENFP...） | 行动档案 + 决策偏好雷达图 |
| 防御绕过 | 无法绕过 | 天然绕过（参与者不知情） |


## 二、核心交互机制

### 2.0 双通道架构（感知层 × 决策层）

关键词交互**不能替代原选择机制，而是与原机制正交分工**。两套信号分开采集、分开报告，只在最终《行为档案》里以"感知 × 决策"双维度呈现：

| 通道 | 采集内容 | 负责维度 | 机制 |
| :--- | :--- | :--- | :--- |
| **感知层** | 读者关注/忽略什么（输入词、顺序、停留、重复） | **S / N** | 关键词自由探索 |
| **决策层** | 读者在关键时刻怎么选（隐性二选一） | **T / F、E / I、J / P** | 隐性分叉（无按钮） |

> **铁律**：每个维度只允许一个信号源。S/N 只走感知层；T/F、E/I、J/P 只走决策层。严禁从关键词输入直接映射 E/I/J/P，避免双重计数污染雷达图。

### 2.1 交互入口：关键词输入框

在每一个勘查/审讯/探索场景中，页面提供：
- 一个**文本输入框**
- 一个**“探查/行动”按钮**（回车亦可触发）

参与者输入**他此刻最想查看、最关心、最怀疑**的人、物、线索或概念。

### 2.2 系统响应：关键词匹配与剧情回馈

系统维护一个**知识图谱/关键词词库**，每个词对应一段剧情文本块。

> ⚠️ 词库映射**只允许 S/N**（及阅读性 T 辅助），禁止映射 E/I、J/P——这两对由决策层隐性分叉采样。

**示例词库（第一案·猎杀营）：**

| 关键词 | 返回内容 | 映射维度 |
| :--- | :--- | :--- |
| `猎字` | 笔迹分析：起笔重、收尾稳、无颤抖 → 情绪可控，高压训练痕迹 | **S（实感细节）** |
| `鞋印` | 足迹特征：原路返回、从容不迫、体重80kg、鞋底磨损特殊 | **S（实感）** |
| `冻伤疤` | 旧疤痕在笔迹下方 → 是凶手的伤，不是死者的 | **N（直觉联想）** |
| `孙狩` | 嫌疑人档案：有竞争、会绳结、但体重65kg vs 真凶80kg | **S（实感）** |
| `关震海` | 真凶浮现：师父、冷链物流、猎杀营产业链 | **N（直觉跳跃）** |
| `动机` | 关震海的深层动机：保护猎场，处决背叛者 | **N（深度洞察）** |

### 2.3 同义词与模糊匹配

参与者不一定输入精确的关键词。系统应支持：
- **同义词映射**：`字` → `猎字`；`脚印` → `鞋印`；`伤疤` → `冻伤疤`；`关` → `关震海`
- **短词包含匹配**：输入`绳` → 匹配`绳结`
- **未匹配时的引导**：返回“没有找到关于‘xxx’的直接线索”，并给出建议词列表

### 2.4 注意力追踪（数据采集核心）

**参与者不知道的是**：系统正在记录他的**整个探索路径**。

| 记录字段 | 说明 |
| :--- | :--- |
| 输入的关键词 | 参与者关注了什么 |
| 输入顺序 | 参与者优先关注什么、次要关注什么 |
| 忽略的词 | 页面提供但未被点击/输入的关键词 |
| 停留时间 | 在某一段剧情文本上停留多久 |
| 重复探查 | 对同一个词多次输入，说明其在纠结/验证 |
| **隐性分叉选择** | 关键时刻读者输入的词，被分类为哪一端（见 2.5） |

这些数据**不被参与者察觉**，因此不存在“答题防御”。

### 2.5 决策层：隐性分叉（与原选择机制的桥梁）

**核心原则：分叉保持、按钮隐形、数据照记、叙事线性收束。**

原机制（三岔口/紧急干预/行动方式/收束方式）**没有失效**，而是被改造成"隐性分叉"：
1. **不出现按钮**：页面上没有任何 A/B/C、甲/乙 选项。
2. **关键时刻由读者自己敲**：剧情设置一个"热点"，读者输入什么，系统按词义把这次输入**分类到一端**（如"追/逃犯/跟上去" → 任务端，"救/门/小满" → 人端）。
3. **叙事照常线性收束**：不管读者敲哪端，剧情都汇合到同一真相，读者感知不到分支——但决策已落库。
4. **代价体现在文本反馈**：收束叙事会根据所选端给一句不同的回响（"代价不同"），强化"我做了决定"的感受，但不改变真相。

**三类隐性分叉（对应原三组决策点）：**

| 隐性分叉 | 读者输入分类 | 映射维度 | 第一案落点 |
| :--- | :--- | :--- | :--- |
| 干预分叉 | 输入追凶类词（追/嫌疑人/汽油桶）vs 救人词（救/门/小满） | **T / F** | 场景④·火场 |
| 行动分叉 | 输入独行词（潜/摸进/自己）vs 联动词（支援/围/等陈默） | **E / I** | 场景④·仓库 |
| 收束分叉 | 输入结案词（结案/定案/锁凶）vs 续查词（木盒/六年前/格槽/十七） | **J / P** | 场景⑤·收束 |

> 隐性分叉的数据字段：`hidden_choice` = "T"/"F"/"E"/"I"/"J"/"P"，记录触发该分叉的 `input_word`。
> 若读者在热点处长时间犹豫（停留>阈值）才输入，可对极端情况打低置信标记，不硬算。

**真读者实测发现的两个补丁（2026-08-03）：**

1. **每对维度只取"第一次输入"计分（first-decision-wins）**。无按钮意味着好奇读者会把同对行动词全试一遍（实测：火场连输"追/救/支援"）。因此同一维度对（E/I、T/F、J/P）只记首个触发输入为决策，后续同类输入**保留审计、不重复计分**。日志字段：`hidden_choice`（计分项，仅首条非空）+ `fork_typed`（审计项，恒记录输入的词属哪端）。
2. **分叉词不进"建议词列表"**。chips 只放感知层词（S/N/T 阅读），避免把四向选择直接摆给读者、削弱"无痕"并诱发全选枚举。行动词须由读者自然输入（叙事用行动指令句引导，如"你只能带走一样东西：跟上去的机会，或那扇门后面的人"）。


## 三、产品形态演进路径

### 阶段一：纯HTML原型（已实现 + 待补）

- **形式**：单个HTML文件，双击在浏览器中运行
- **能力**：输入关键词 → 匹配词库 → 返回文本块 → 记录探索历史
- **待补能力**：① 隐性分叉分类（热点输入的词 → T/F/E/I/J/P）；② 场景切换触发器；③ 停留时间打点
- **用途**：验证交互机制是否能够降低防御心理，测试词库覆盖率 + 隐性分叉是否够“隐”
- **状态**：🔄 词库部分已构建，隐性分叉模块待实现

### 阶段二：轻量级线上版本（推荐下一步）

- **形式**：单页Web应用（SPA），部署在静态托管（如Vercel / GitHub Pages）
- **新增能力**：
  - 多场景切换（现场勘查 → 审讯室 → 冷库 → 结案）
  - 探索历史持久化（localStorage 或简单后端）
  - 章节进度存档
  - 后台记录导出（供分析使用）
- **成本**：极低（纯前端 + 静态数据）

### 阶段三：完整互动叙事产品

- **形式**：Web App / 小程序 / 渐进式Web应用
- **新增能力**：
  - 丰富的场景插画/氛围音效
  - 更复杂的词库（16案 × 每个场景20-50个关键词）
  - NLP自然语言处理（支持完整句子输入，识别意图）
  - 16案全部完成后，生成“行动档案”与“决策偏好雷达图”
  - 可选的“匿名数据贡献”机制，用于优化算法
- **数据架构**：
  - 前端：React / Vue + 状态管理
  - 后端：Node.js / Python（存储行为日志 + 生成报告）
  - 数据库：PostgreSQL（用户行为序列） + Redis（会话缓存）


## 四、用户侧体验流程

### 4.1 阅读/探索阶段
1. 用户打开页面，进入第一案场景。
2. 系统呈现一段场景描述 + 输入框 + 建议词列表（可选）。
3. 用户输入关键词，系统返回对应文本块。
4. 用户继续输入新词，或者输入“跳过”推进剧情。
5. 在**关键热点**（如火场、结案前），系统不出按钮——但读者输入的词会被隐性分类为决策端并落库。
6. 系统默默记录每一步操作。

### 4.2 结案反馈阶段（16案完成后）
1. 系统不弹窗“你是INTJ”。
2. 系统生成一份**《行为分析档案》**：
   - 列出了你在各案中最关注的三类线索
   - 列出了你最容易忽略的线索类型
   - 列出了你在关键时刻的决策倾向
3. 在档案底部，用自然语言附注：“以上行为模式，与‘战略直觉型’（INTJ）有较高重合度。”
4. 用户的第一反应是：“这个系统好懂我。”——而不是“我被测了。”


## 五、数据隐私与伦理

### 5.1 无痕投射的伦理边界
- 系统记录的是**行为序列**（输入词、时间戳、顺序），不记录个人身份信息。
- 用户有权在完成阅读后清空所有本地数据。
- 若启用云端分析，必须经过用户**明确知情同意**。

### 5.2 数据用途说明
- 仅用于优化词库匹配精度和剧情节奏设计。
- 不用于商业推荐、不用于招聘筛选、不用于任何形式的“人格评判”。
